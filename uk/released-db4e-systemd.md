Нещодавно я опублікував на PyPI та GitHub невеликий модуль Python: [`db4e-systemd`](https://pypi.org/project/db4e-systemd/). Це легка обгортка над `systemctl`, яка дозволяє керувати службами (запускати, зупиняти, вмикати, вимикати й перевіряти їхній стан) безпосередньо з Python, використовуючи простий і лаконічний код.

Я написав його для власного проєкту `db4e` — повнофункціонального менеджера розгортання компонентів для майнінгу Monero. Але подумав, що клас `Db4eSystemd` може бути корисним і сам по собі. І, схоже, мав рацію.

---

# 16 клонувань… А потім ще 35?

Налаштувавши пакет на PyPI та додавши посилання на репозиторій GitHub, я тихенько опублікував версію `1.0.0` і взявся за інші справи. Наступного дня з цікавості зазирнув у GitHub Insights: 16 унікальних користувачів клонували репозиторій. Ще через день? Уже 35. І все це без жодного просування.

Схоже, в екосистемі справді *бракувало* саме такого інструмента — і `db4e-systemd` добре заповнює цю прогалину.

---

# Навіщо існує цей модуль

У Python завжди можна було керувати службами різними хитрощами через subprocess, але бракувало зрозумілої, природної для Python обгортки над `systemctl`, яка просто працює та не тягне за собою гору залежностей. Я хотів:

* Клас, екземпляр якого створюється з назвою служби
* Методи на кшталт `.start()`, `.stop()`, `.restart()`, `.enable()`, `.disable()`, `.status()`
* Властивості на кшталт `.active`, `.enabled`, `.installed`, `.pid`
* Акуратне опрацювання stdout/stderr

Саме це я й створив. Один клас, менше ніж 200 рядків коду й жодних залежностей поза стандартною бібліотекою.

# Створений для повторного використання, задокументований для пошуку

Коли я побачив, що люди справді клонують репозиторій, то впорядкував пакування:

* Написав `README.md` із прикладами використання
* Створив `CHANGELOG.md`
* Налаштував належні `setup.py` і `pyproject.toml`
* Позначив випуски тегами, опублікував пакет на PyPI й додав його до своєї бази знань на GitHub Pages

Я навіть написав [посібник із публікації на PyPI](https://kb.osoyalce.com/pages/PyPI.html) для тих, хто хоче випускати власні пакети.

# Погляд у майбутнє та ідея одного відсотка

Хоча наразі `db4e-systemd` завершений, він відіграє важливу роль у більшій системі — [Database 4 Everything](https://db4e.osoyalce.com/). Там я відстежую час безперервної роботи, щоб реалізувати «модель пожертви 1%»: п’ять хвилин спільного майнінгу за кожні вісім годин роботи. Імовірно, ця логіка теж житиме в модулі.

В опенсорсі ми часто мислимо масштабно, але інколи саме найменші інструменти охоплюють найбільше людей. Це чудове нагадування. Обов’язково продовжу в тому ж дусі.
